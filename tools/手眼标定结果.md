# 手眼标定结果（2026-10-28）

## 先看这里：哪个文件是 TCP/手眼标定

当前抓取管线使用的是：

```text
calib_results/2026-10-28_16-09-08_handeye.json
```

这个文件是 **eye-in-hand 手眼标定**，不是夹爪尖端接触标定。JSON 里的：

```json
{
  "result": {
    "matrix4x4": [[...], [...], [...], [0, 0, 0, 1]]
  }
}
```

`result.matrix4x4` 是 **相机在法兰/TCP 坐标系下的位姿**，即
`T_flange_cam`（JSON 的 frame 字段写作 `T_tcp_cam: camera in flange/TCP frame`）。
这里的 TCP 是驱动 `tcp_offset=0` 时的法兰坐标系；夹爪垫中心 TCP 还要再乘
`configs/real_piperx.yaml` 里的 `arm.flange_tcp_xyz_m` /
`arm.flange_tcp_rpy_deg`。

不要把下面的夹爪尖端文件当成手眼结果：

```text
calib_results/2026-10-28_16-18-09_tip_cam.json
```

它是 **夹爪尖端接触标定**，包含 `T_tip_cam` 和 `T_flange_tip`，用于夹爪尖端
验证；当前 GraspNet 抓取管线不使用它。`2026-10-28_15-50-22_handeye.json`
是归档的早先尝试，也不用于当前配置。

```python
assert T_flange_cam.shape == (4, 4)

# 平移单位是米；旋转是 3x3 正交矩阵
```

Python 抓取管线里的读取位置是
`piper_mujoco/utils/piperx_real_env.py`：

```python

T_flange_cam = handeye["result"]["matrix4x4"]
T_tcp_cam = np.linalg.inv(T_flange_tcp) @ T_flange_cam
T_base_camera = T_base_tcp @ T_tcp_cam
```

`configs/real_piperx.yaml` 的 `camera.handeye_json` 指向这个文件。只读校验可运行：

## 结果

- 模式：eye-in-hand，相机固定在末端
- 标定板：ChArUco 7×5，方格 30 mm，码 22 mm，DICT_4X4_50
- 样本：**16 组**（原计划 22 组）
- 方法：PARK
- 一致性残差：**平移 2.77 mm RMS**（最大 5.69 mm），**旋转 0.76° RMS**（最大 1.52°）
- 姿态跨度 52.1°，末端位置分散 99 mm
- 结果文件：`calib_results/2026-10-28_16-09-08_handeye.json`

本次由 `skills/piper-handeye-calibration` 自动采集，驱动速度 5%。第 5 个纯平移候选 `-100 mm x` 触发关节限位（`arm_status=4`），后 6 个平移候选被跳过，因此只采到 16 组；残差和多样性仍通过验收标准。

## 与上一版对比

2026-10-24 旧结果（`calib_results/2026-10-24_14-37-25_handeye.json`）：

- 方法 DANIILIDIS，22 组
- 平移 2.69 mm RMS，旋转 0.98° RMS

2026-10-28 的新结果旋转精度略好（0.76° vs 0.98°），平移略差（2.77 mm vs 2.69 mm），但完整通过多样性验收，当前配置使用新结果。

## 注意

- 标定板必须固定、压平；透明/反光物不要放在板上。
- 采集时必须等机械臂完全停稳（≤0.8 mm / 0.25° 持续 1 s），否则残差会明显变大。
- skill 的 `auto_calibrate.py` 在保存结果后有一个返回解包 bug（`print_result()` 返回 None），会打印 `TypeError`，但结果 JSON 已经保存，不影响标定值。
- 驱动速度、关节限位和机械臂使能状态不要在标定过程中手动改变。
